Message formats, the simulator line protocol, bit layouts, and state machines.

1. WebSocket message catalog

Browser → server

typeFieldsMeaning
compilelang ("vhdl" | "verilog"), code, top (optional), vcd (bool)Stop current sim, compile, start new sim
stepn (cycles, 0 allowed), sw (18 chars, SW17 first), key (4 chars, KEY3 first)Apply inputs, run n cycles
stop—End the sim; return VCD if recorded

Server → browser

typeFieldsMeaning

2. Simulator line protocol

DirectionLineMeaning
server → simS <n> <sw18> <key4>Set inputs, wait 1 ns, check, then run n cycles
server → simQQuit cleanly (flushes VCD)
sim → serverO <k> <bits83>Outputs changed after cycle k (k = 0 means after inputs applied)
sim → serverF <n> <bits83>Final outputs of this batch
sim → serverDBatch done
sim → serveranything elseForwarded to Console (e.g. $display)

3. Output bit layout (83 bits)

All outputs are concatenated MSB first. HEX bit i drives segment i (0 = a ... 6 = g) and is lit when 0.

7. Live waveform data model

Transitions are appended only when the value changes. If two arrive at the same time the later one replaces the earlier. Each row keeps up to 200,000 transitions, dropping the oldest quarter when full. VCD rows use the same shape, with time in nanoseconds.
