Solution Architecture

The problem, the options, and the key decisions behind the design.

1. Problem statement

Digital-logic courses test Verilog/VHDL on FPGA boards. Commercial boards such as the DE2-115 cost several hundred dollars, so students rarely own one and lab time is limited. Text-only simulators exist, but they don't give the tactile "flip a switch, see an LED" loop that makes hardware intuitive, and waveform tools like GTKWave have a steep learning curve.

Goal: a free tool where a student writes HDL, presses one button, and interacts with a realistic virtual board, with debugging views built in.

2. Goals and non-goals

Goals

  • Full VHDL-2008 and Verilog/SystemVerilog language support
  • Pin names identical to the real DE2-115 so lab code works unchanged
  • Interactive inputs (switches, momentary and latched keys)
  • Live waveform of all board I/O, plus a full internal-signal recording
  • Run locally with one command; path to a hosted website later
  • Clear errors: highlighted lines, undefined (X/U) values flagged on the board

Non-goals (v1)

  • Synthesis, timing analysis, or bitstream generation
  • Real-time 50 MHz simulation
  • Peripherals beyond switches/keys/LEDs/HEX (VGA, SDRAM, UART, audio)
  • Multi-user accounts and project storage
  • Gate-level or analog accuracy

6. Architecture decision records

IDDecisionRationaleConsequence
ADR-1Use GHDL and Icarus Verilog as the simulation enginesMature, free, cover both languages fullyUsers must install them; behaviour matches what instructors' tools report
ADR-2Talk to the simulator through a line-based stdin/stdout protocol embedded in a generated testbenchWorks identically in both simulators with no plugins (no VPI/VHPI C code)Throughput limited (~250k cycles/s) by per-cycle checks; simple to debug
ADR-3Generate the testbench from the student's port listStudents keep their normal top-level; widths and types adapt automaticallyNeeds a lightweight port parser per language (regex based)
ADR-4WebSocket with request/response stepping (one batch in flight)Natural back-pressure; UI never floods the simulatorLatency of one round trip per batch; batches grow with clock speed
ADR-5Report only output changes, capped at 256 per batch, plus final stateKeeps messages small at high clock speedsLive waveform may skip changes at high speeds; region is shaded and VCD gives exact detail
ADR-6Record internal signals via simulator-native VCD, loaded on StopZero custom instrumentation; standard formatInternal view is post-mortem, not live; files grow fast (40 MB cap)
ADR-7Vanilla JS, no framework or build stepEasy to read and run; one python3 server.pyManual DOM management; fine at this size
ADR-8Model the DE2-115 specifically, with canonical pin namesMatches the target course's board and Quartus pin filesOther boards need a board-description abstraction later
