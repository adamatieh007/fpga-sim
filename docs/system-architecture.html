System Architecture

Runtime containers, processes, interfaces, timing, and limits.

1. Container view

Three runtime containers: the browser application, the Python session server, and short-lived simulator processes. Temporary files live in a per-session working directory that is deleted on stop or disconnect.

2. Process and concurrency model

  • A single Python process runs an asyncio event loop. Every browser tab opens one WebSocket and gets its own SimSession.
  • Each session owns at most one live simulator process. Recompiling stops the old one first.
  • Messages from a tab are handled strictly in order. A step awaits the simulator's D line before the next message is read, so steps never overlap.
  • A background task per session pumps the simulator's stderr (VHDL report, assertion failures, runtime errors) to the Console tab.

4. Clock and time model

Real time, simulated cycles, and simulator time are three different clocks. The browser converts the chosen clock speed into a number of cycles owed, the server forwards them in batches, and the wrapper toggles CLOCK_50 with a 20 ns period.

One simulated cycle is 20 ns in VCD time (matching 50 MHz), plus 1 ns per batch for input settling. In the live waveform the time axis is in cycles, and the rising edge of cycle k is drawn at base + k - 0.5.
